> **Спершу прочитай [PROJECT-CONTEXT.md](PROJECT-CONTEXT.md).** Там персональний

> винятків і перелік того, що тут **не** перевіряється автоматично. Цей файл —

## Що це

Сайт театральної студії: публічні сторінки українською й англійською плюс
адмін-панель на Firebase. Опорний проєкт пакета — більшість інваріантів канону
народилися саме тут, тож перш ніж вигадувати перевірку, подивись, чи її вже
немає в `src/*.test.ts`.

## Архітектура

- **Фреймворк:** SvelteKit 2 + Svelte 5 (**виключно** руни).
- **Профіль:** `static`, власний домен, `base = ''`. Серверного рантайму немає:
  ні form actions, ні `+server.ts`, ні `hooks.server.ts`. Дані — з Firestore на
  клієнті й із prerendered вмісту.
- **Стан:** класи-контролери в `.svelte.ts`. Module-level синглтон — панівна
  форма; `$effect` у його конструкторі кидає `effect_orphan`.
- **Сховище:** фасад `src/lib/services/storage.ts`, префікс `teatralo4ka_`
  (`src/lib/config/storage.ts`).
- **Дані:** усе, що приходить із Firestore, проходить `zod`-схему зі
  `src/lib/schemas/`. Схеми **відкидають** непридатне й нічого не підставляють —
  типові значення живуть в одному місці, у `DEFAULT_*`.
- **HTML із бази:** лише через `isomorphic-dompurify`. Звичайний `dompurify`
  падає під час prerender.
- **i18n:** `svelte-i18n` + типізована `schema.ts`. Мова — префікс шляху
  (`/en/…`, `uk` на голому), реалізований хуком `reroute` у `src/hooks.ts`.

## НЕ РОБИ

| Заборонено | Замість цього |
|---|---|
| `writable()`, `readable()`, `derived()` зі `svelte/store` | `$state` / `$derived` у класі-контролері |
| `import { page } from '$app/stores'` | `$app/state` |
| `localStorage.getItem(...)` напряму | `storage` із `$lib/services/storage` |
| `{@html}` над даними з Firestore без санітизації | `isomorphic-dompurify`, і `eslint-disable-next-line` із причиною поруч |
| `${base}/шлях` для посилань | `resolve('/шлях')` з `$app/paths` |
| `${base}/images/x.svg` для файлів | `asset('/images/x.svg')` |
| `toLocaleString()` без аргументу | явна локаль: без неї береться локаль **системи**, а не мова сайту |
| `any` | конкретний тип, `unknown` або дженерик |
| `console.log` у коді застосунку | `errorLogger.logError()` / `.logWarning()` / `.logInfo()`. Правило `error`; у `scripts/` і конфігах воно вимкнене — там `console` і є виводом |
| Голий `Set` / `Map` як реактивний стан | `SvelteSet` / `SvelteMap` зі `svelte/reactivity` |
| `width`/`height` числом поруч із тегом для СВОГО файлу | `imageSize('/шлях')` із `$lib/config/localImages` — числа там звіряються із заголовками файлів на диску |
| Виводити склад вистави з групи (`memberIds` × `playIds`) | Читати `playId` в анкетах: склад авторський і поштучний. Пояснення й заміри — у докблоці `src/lib/data/plays.ts` |

Кожен рядок цієї таблиці, крім останнього, — правило ESLint. Вимкнути правило
можна лише разом із записаною поруч причиною (CODE-QUALITY-v8 § 6.4.1);
інваріант `src/eslint-baseline.test.ts` падає, якщо хтось вимкне його мовчки.

Останній рядок — не ESLint, а юніт-інваріант `src/image-dimensions.test.ts` плюс
`src/lib/config/localImages.test.ts`: перший вимагає, щоб місце під зображення
було відведене, другий звіряє числа із заголовками файлів на диску.

## Архітектура розділу «Дорослі» (/residents/adults)

- **ТРИ ОСІ, а не одне поле** (розділено 2026-08-24; до того все це жило в `category`):
  - `category` — **функціональна роль**. Єдине джерело переліку значень —
    `MASTER_CATEGORIES` у `data/masters.ts`; сюди він НЕ переписується, бо копія
    розходиться мовчки. Поля може не бути зовсім, і це означає «роль справді
    невідома», а не «забули заповнити».
  - `status` — **життєвий цикл людини**: `active`, `former`, `honorary`.
    `former`, а не `history`: розділ зветься «Історія школи», і поки значення
    звалося так само, два питання виглядали одним.
  - **повнота даних НЕ зберігається** — обчислюється (див. наступний пункт).
  - Ціна старого змішування: `needsClarification` стояло у двох третинах записів
    і **стирало в них роль**; `isHonorary` дублював `status === 'honorary'`, і
    `MasterCard` перевіряв один факт **тричі**. Поле `isHonorary` **видалено**.

> Дві верхні осі й нижня розходяться НАВМИСНО, і це не помилка даних: роль —
> факт про людину, розділ — місце на сторінці. Франковська лишається

- **Розділ на сторінці — ПОХІДНА (`masterSection` у `data/masters.ts`)**, не поле.
  Порядок умов значущий: `honorary` → явний виняток → `former` → роль. Більше
  нічого: ні фотографія, ні посада, ні повнота ПІБ на розділ **не впливають**, і
  кожен із трьох винятків має причину в даних.
  - **посада** — її не має жоден із трьох «Світлої пам'яті» й шість із семи
    «Історії школи»: умова з нею спорожнила б обидва розділи;
  - **повне ПІБ** було умовою кілька годин 2026-08-24 і виганяло зі змістових
    розділів людей, яких там чекають (Рибакову Надію В., Шевчука Олега В.,
    Надопту Світлану — з «Історії школи», Ганбарова Ельміра — з педагогів).
    Коротке ім'я — це те, як людину записали, іноді свідомо;
  - **фотографія** була умовою того ж дня й прибрана на пряме рішення автора:
    «всі без фотографії — в «Потребують уточнення»» це умовне правило для розбору
    купи, а не факт про людей, і фіксувати його в коді не треба. Ціна прибирання
    заміряна — переїхали **чотири** записи (Дерепа, Рибальченко Д.Д., Козовякін,
    Сухобоєвська: усі `former`, без знімка й без ролі), решта тих, хто без фото, і
    так не має ролі. Картка без знімка малює заглушку-камеру.
  Тобто «Потребують уточнення» — це **невідома роль** плюс **явні винятки**. Склад
  розділів — у таблиці під гейтом вище, разом із причиною, чому він розходиться
  з `category`.
- **`unconfirmed: true` — ЯВНИЙ ВИНЯТОК**, «тримати в технічному розділі, хоч
  решта полів веде до змістового». 2026-08-24 автор назвав дванадцять таких
  записів, і спільного ПОЛЯ в них не виявилося: Пирогова і Стельмах — так само
  лише прізвища — лишилися в «Історії школи», а Пруба із записаним предметом
  поїхала. Тобто межа «змістовий розділ проти технічного» з даних **не
  виводиться** — це знання про людей. `true`, а не `boolean`: «підтверджений» каже
  сама відсутність поля. Гейт вимагає, щоб кожен прапорець **справді змінював
  розділ** — на записі, який і без нього в технічному розділі, він мертвий рядок
  (один такий уже був і прибраний того ж дня: `unconfirmed: false` у Ткач Ганни,
  поки розділ залежав від фотографії).
- **Видимість — `visibility?: 'listed' | 'linked' | 'direct'`, поля немає = `listed`.**
  Три рівні спільні з випускниками (`config/visibility.ts`; розділ «Види людей і
  три рівні видимості» у PROJECT-CONTEXT.md). Політика в ОДНОМУ модулі
  `config/mastersVisibility.ts`, і рівень поза переліком означає **чотири
  обіцянки**: немає картки у списку, `noindex` без `canonical`/`hreflang`, немає
  адреси в `sitemap.xml`, **сторінка лишається живою**. Останнє — вимога, а не
  недогляд: на частину майстрів указують анкети випускників, і зникнення сторінки
  зробило б із цих посилань 404. У `HIDDEN_ROUTES` це НЕ додається: там кожен запис
  зобовʼязаний бути ще й у `prerender.entries`, `HIDDEN_ENTRIES` і `robots.txt`, а
  `Disallow` для майстра дав би протилежне потрібному — закриту від краулера
  сторінку, у якій `noindex` не прочитають ніколи. Межа названа вголос: сам
  `masters.index.json` їде в клієнтський чанк цілком, тож прихований запис у
  бандлі лишається.
  **Навіщо це взагалі:** сторінки майстрів довго були помітною часткою мапи
  сайту, і в багатьох із них бракує посади, предметів або фотографії (скільки
  саме — рядок «прогалини» в таблиці під гейтом вище). Сам список при цьому
  показується лише після `H`×7 (`adultsVisibility`), тобто список був схований,
  а профілі — в індексі.
- **«Роки роботи» — `periods` у ПРОФІЛІ, не в індексі.** `{ from: number; to: number | null }[]`,
  `to: null` = дотепер, термінів може бути кілька («2012–2016, 2022 — дотепер»).
  Не в індексі, бо той імпортується модулем і їде в бандл цілком — терміни всіх
  до одного везлися б на кожну сторінку заради одного рядка на сторінці профілю
  (та сама причина, що в `bio` й `socials`). На сторінці показується **сума**
  (`yearsOfService`), а не самі роки: «2012–2016, 2022 — дотепер» це вісім років,
  а не чотирнадцять. Три форми слова «рік» — `yearsLabelKey`, ICU-плюралізації в
  проєкті немає ніде.
- **Порожній `departments` (і відсутні `subjects`) означає РІЗНЕ залежно від ролі.**
  Для тих, хто не викладає (`administration`, `production`, `it`, `support`) — «НЕ
  СТОСУЄТЬСЯ»: школа в них уся, а не одне відділення, і предметів немає. Для
  педагогічної або невідомої ролі — «НЕ ЗНАЄМО», тобто прогалина, яку треба
  заповнити. Скільки таких записів усього — рядок «прогалини» в таблиці під
  гейтом вище; розкладка на «не стосується» і «невідомо» виводиться з ролі й
  тому окремо не записується. Правило не суто «за роллю»: записане показуємо
  завжди, бо у двох людей зі `support`/`it` предмети Є (Дранков — акторська
  майстерність, Запольнов — театральне мистецтво). Сторінки малюють
  обидва поля через `{#if length > 0}`, тож порожнє на сайті зникає само; звіт
  `.temp/masters-report.txt` тим самим правилом ставить 🟥 там, де питання має
  сенс, і прибирає рядок там, де відповіді не буде.
- **3 режими відображення:** `gallery` (Театральні вертикальні постери 2:3 `720×1080 px`, за замовчуванням), `cards` (Картки), `compact` (Мінімалістична сітка аватарів з hover popover). Стан зберігається в `localStorage` (`adults_view_mode`).
- **Порядок сортування в категоріях: фіксований лише в керівництві, решта рахує учнів.**
  - `administration`: фіксована послідовність (1. Олена Ткач, 2. Оксана Панченко, 3. Наталія Шалашна, 4. Любов Франковська, 5. Тетяна Коренчук — директорка, заступниця, далі бухгалтерія). Тут порядок — службова ієрархія, яку нізвідки не вивести. Лілія Величко прибрана 2026-08-24 (переїхала в «Історію школи», запис тут був мертвий), тоді ж троє завідувачок поїхали у власний розділ `heads`.
  - **усі інші розділи** — один спільний порядок: за кількістю учнів за спаданням, далі «з фотографією вперед», далі алфавіт за `fullName` (`localeCompare(…, 'uk')`). Поля `graduatesCount` у `masters.index.json` немає ні в кого — його додає `+page.ts` із `getGraduatesByMaster`, і воно ЖИВЕ: учнів указано приблизно в кожного п'ятого майстра, у решти нуль, тож порядок справді міняється. До 2026-08-24 тут і в коментарі коду стояло, що це порівняння завжди дає нуль — неправда, яка описувала сортування, якого немає. Точні числа тут навмисно не записані: вони міняються від кожної правки анкети випускника, а перевірити їх можна лише прогоном `getGraduatesByMaster`.
  - Фіксовані переліки для `heads` (театральне → художнє → музичне) і `support` (Стоянова першою) прибрані 2026-08-24 на прохання автора: у цих розділах місце людини задає її внесок, а ручний перелік лише перекривав би його, старіючи з кожною правкою даних випускників. «Потребують уточнення» доти сортувався алфавітом — тепер так само за учнями, бо їх мають і там (Ткач Ганна 3, Кульбаба 2, Серебряннікова 2).
- **Перейменування slug майстра — робота з редиректом, а не заміна рядка.** Стара
  адреса лежить у `sitemap.xml`, тож мапа `RENAMED_SLUGS` у
  `src/routes/residents/adults/[slug]/+page.ts` веде з неї на нову (причини, чому
  саме там, а не окремим маршрутом-заглушкою — у коментарі поруч). Перейменувати
  треба **чотири місця**: профіль, аватар, портрет і вихідник у
  `assets/masters-raw/` — останній обовʼязково, бо `build-master-photos.ts` бере
  id із НАЗВИ файлу. Якщо на `id` вказують випускники (`masters[].id` у
  `graduates.index.json` і в `static/graduates/profiles/*.json`), їх треба
  правити тим самим комітом — інакше майстер тихо втрачає учнів.
- **Конвеєр фотографій викладачів:**
  - Повноформатні вихідники 1:1 зберігаються в `assets/masters-raw/{id}.webp` (WebP q=50).
  - Команда `npm run build:masters` генерує квадратні аватари `static/masters/{id}.webp` (480×480) та вертикальні постери `static/masters/portraits/{id}.webp` (720×1080), автоматично оновлюючи `masters.index.json` та `static/masters/profiles/*.json`.
- **Правило тестування користувача:** Користувач сам візуально перевіряє інтерфейс у браузері. НЕ використовувати `browser_subagent` для візуального тестування UI.

## Конвенції

- **Іменування:** компоненти `PascalCase.svelte`, утиліти `camelCase.ts`,
  контролери з рунами — обов'язково `.svelte.ts`.
- **`data-testid`:** стратегія **B — зберігати в production** (плагіна видалення
  немає, тож це записано, а не вдається за A). Конвенція — у
  TESTID-AND-NAMING-v8; перевірки: `src/testid-conventions.test.ts` статично,
  `e2e/testid.spec.ts` у рантаймі.
- **Тести:** Vitest під `src/` і `vitest/support/`, Playwright — у `e2e/`, проти
  **зібраного** сайту (`npm run test:e2e` спершу робить `build`).

## Команди перевірки та збірки

```
npm run check          # svelte-check, має бути 0 помилок і 0 попереджень
npm run lint           # eslint, має бути 0 помилок
npm test               # юніт-інваріанти vitest (107 файлів; число під гейтом doc-numbers)
npm run build:masters  # збірка веб-аватарів та постерів із assets/masters-raw/
npm run bump-version   # автоінкремент версії
npm run build          # збірка сайту; postbuild перевіряє sitemap і бандл
npm run test:e2e       # Playwright проти build/
```

Локально ці п'ять команд — те саме, що робить CI. Різниця одна: `npm run build`
і Playwright у CI виконуються лише в `deploy.yml` на `main`, тож перед пушем
туди їх варто прогнати руками — на pull request їх не буде.

**Результат треба побачити, а не припустити.** Твердження «правило виконано»
робиться після прогону, а не замість нього. Частину дефектів цього проєкту видно
**лише** у `build/` — саме тому `postbuild` існує окремо
(AI-AGENT-PITFALLS-v8 § 2).
